# TR002: Type must be sealed

| | |
|---|---|
| Category | Design |
| Default severity | Warning |
| Code fix | Yes, when sealing can't break the build |

## Cause

A non-abstract class or record that inherits from or implements a rule set's `match` types isn't
`sealed`, and the rule set sets `require_sealed = true`.

## Configuration

```ini
[*.cs]
typerules.endpoints.match = T:MyApp.IEndpoint
typerules.endpoints.require_sealed = true
```

## How it's checked

Abstract and static classes are skipped, since they can't be sealed. Structs and record structs
are always sealed.

TR002 is reported even when another type derives from the class. The rule set says matched
classes must be sealed, so a matched class with subclasses breaks it; the fix is usually to make
the base class `abstract`.

## Example

```csharp
internal class GetUsersEndpoint : IEndpoint { }   // TR002
```

```
warning TR002: 'GetUsersEndpoint' must be sealed, as required by rule set 'endpoints'
```

## Code fix

**Make '...' sealed** adds `sealed`. It's only offered when that can't break the build:

- no class in the solution derives from the type
- the type declares no new `virtual` members (CS0549 in a sealed class)
- the type declares no new `protected` members (CS0628 warning in a sealed class)

Overrides are fine.
