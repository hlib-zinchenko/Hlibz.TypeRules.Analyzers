# TR301: Setter is more accessible than its rule set allows

| | |
|---|---|
| Category | Design |
| Default severity | Warning |
| Code fix | Yes, when an accessor modifier can't break the build |

## Cause

A property declared by a type that inherits from or implements a rule set's `match` types has a
`set` (or `init`) accessor accessible from more places than the rule set's
`max_setter_accessibility` allows.

## Why

Entities and aggregates guard their invariants by changing state only through their own methods
(`order.Cancel()`, not `order.Status = Cancelled`). A public setter lets any caller skip them.

## Configuration

```ini
[*.cs]
typerules.entities.match = T:MyApp.Domain.Entity`1
typerules.entities.max_setter_accessibility = private
# Optional: don't count init accessors.
typerules.entities.allow_init = true
```

`max_setter_accessibility` takes the same levels as `max_accessibility`: `public`,
`protected_internal`, `internal`, `protected`, `private_protected` or `private`. For example,
`private_protected` still lets a base entity type's properties be set by its derived types in the
same assembly.

`init` accessors count by default, since `new Order { Status = Cancelled }` bypasses invariants
just as a setter does. Set `allow_init = true` to exempt them. `allow_init` without
`max_setter_accessibility` is reported as [TR000](TR000.md).

## How it's checked

- Every property the matched type **declares**, static ones and indexers included. A property
  inherited from a base class is checked on the base class, if that one is matched.
- **Effective accessibility**: the accessor's own level narrowed by the type's. A `public set` in
  an `internal` class is internal, so it passes `max_setter_accessibility = internal`.
- Overrides and explicit interface implementations are skipped: their shape is dictated by what
  they override or implement. Get-only properties, and properties in generated code, are too.
- A positional record's properties have public `init` accessors, and are reported at the
  parameter.

## Example

```csharp
public sealed class Order : Entity<OrderId>
{
    public OrderStatus Status { get; set; }   // TR301
}
```

```
warning TR301: The set accessor of 'Order.Status' is public, but rule set 'entities' allows at most private
```

## Code fix

**Make the set accessor private** adds (or replaces) the accessor's modifier with the most
permissive level within the maximum that's more restrictive than the property itself, as C#
requires. A protected level is never chosen in a struct, static class or sealed class.

No fix is offered where an accessor modifier would break the build:

- `required` properties (their setter must be as accessible as the type: CS9032)
- properties that implement an interface member
- `virtual`, `abstract` and `override` properties
- properties without a getter (an accessor modifier needs both accessors: CS0276)
- positional record properties, which have no accessor syntax to change
