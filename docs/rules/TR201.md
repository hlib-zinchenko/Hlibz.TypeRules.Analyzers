# TR201: Constructor is more accessible than its rule set allows

| | |
|---|---|
| Category | Design |
| Default severity | Warning |
| Code fix | Yes, when the change still compiles |

## Cause

A constructor of a non-abstract class, struct or record that inherits from or implements a rule
set's `match` types can be called from more places than the rule set's
`max_constructor_accessibility` allows. That includes the implicit default constructor of a class
that declares none, and primary constructors.

## Why

A public constructor lets any caller create an aggregate or value object in any state it likes.
Creating it through a factory method (`Order.Place(customer, lines)`, `Email.Create(text)`) keeps
the invariants and the domain events of creation in one place, and the constructor private.

An ORM that needs a parameterless constructor can still use a private one: EF Core does.

## Configuration

```ini
[*.cs]
typerules.aggregates.match = T:MyApp.Domain.IAggregateRoot
typerules.aggregates.max_constructor_accessibility = private
```

`max_constructor_accessibility` takes the same levels as `max_accessibility`: `public`,
`protected_internal`, `internal`, `protected`, `private_protected` or `private`. Use `internal`
to allow a factory or builder elsewhere in the domain assembly.

## How it's checked

- **Effective accessibility**: the constructor's own level narrowed by the type's. A `public`
  constructor of an `internal` class is internal.
- **The implicit default constructor** of a class that declares no constructor is public, and is
  reported on the type. So are primary constructors, including a positional record's.
- **Skipped**: abstract classes (their constructors exist for derived types to call), static
  constructors, a struct's implicit parameterless constructor (it can't be restricted, and
  `default` creates a struct anyway), and a record's implicit copy constructor (only `with`
  expressions call it, on an existing instance).
- When a type matches several rule sets, the maximum shown is the strictest of all of them.

## Example

```csharp
public sealed class Order : IAggregateRoot
{
    public Order(CustomerId customer) { }   // TR201
}
```

```
warning TR201: Constructor 'Order(CustomerId)' is public, but rule set 'aggregates' allows at most private
```

## Code fix

**Make the constructor private** sets its accessibility to the most permissive level within the
maximum (no `protected` level in a struct or sealed class). Any caller outside that level stops
compiling, so the change is applied speculatively first and **only offered if every document
that references the constructor still compiles**. For a parameterless constructor that includes
documents that use the type, since `new()` constraints call it without naming it.

When the fix isn't offered, those callers need to move to a factory method first. There's no fix
for implicit default and primary constructors, which have no declaration to change.
