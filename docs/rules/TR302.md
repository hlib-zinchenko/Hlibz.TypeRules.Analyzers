# TR302: Mutable collection is exposed

| | |
|---|---|
| Category | Design |
| Default severity | Warning |
| Code fix | Yes, when the change still compiles |

## Cause

A property or field declared by a type that inherits from or implements a rule set's `match`
types is visible outside the type and has a mutable collection type, and the rule set sets
`readonly_collections = true`.

## Why

A private setter doesn't protect a collection: `order.Lines.Add(line)` changes the entity without
going through it. Expose a read-only view over a private collection, and change it through the
entity's own methods:

```csharp
private readonly List<OrderLine> _lines = [];

public IReadOnlyList<OrderLine> Lines => _lines;

public void AddLine(OrderLine line) { /* check invariants */ _lines.Add(line); }
```

## Configuration

```ini
[*.cs]
typerules.entities.match = T:MyApp.Domain.Entity`1
typerules.entities.readonly_collections = true
```

## What counts as mutable

Single-dimensional arrays, and these types or any class deriving from them:

| Kind | Types | Read-only equivalent |
|---|---|---|
| List | `List<T>`, `IList<T>`, `Collection<T>`, `ObservableCollection<T>`, `T[]` | `IReadOnlyList<T>` |
| Dictionary | `Dictionary<K,V>`, `IDictionary<K,V>`, `SortedDictionary<K,V>`, `SortedList<K,V>`, `ConcurrentDictionary<K,V>` | `IReadOnlyDictionary<K,V>` |
| Set | `HashSet<T>`, `ISet<T>`, `SortedSet<T>` | `IReadOnlySet<T>` (.NET 5+), else `IReadOnlyCollection<T>` |
| Other generic | `ICollection<T>`, `LinkedList<T>`, `Queue<T>`, `Stack<T>`, `ConcurrentBag<T>`, `ConcurrentQueue<T>`, `ConcurrentStack<T>` | `IReadOnlyCollection<T>` |
| Non-generic | `ArrayList`, `Hashtable`, `IList`, `IDictionary`, multi-dimensional arrays | none |

It's a list rather than "implements `ICollection<T>`" on purpose: immutable and read-only
collections (`ImmutableArray<T>`, `ReadOnlyCollection<T>`) implement `IList<T>` too, with mutators
that throw. Those, `IEnumerable<T>` and the `IReadOnly*` interfaces are never reported.

## How it's checked

- Properties and fields the matched type declares, with **effective accessibility** above
  private: anything visible outside the type, including `protected` and `internal`. Private
  backing collections are the point, so they're never reported.
- Overrides, explicit interface implementations, constants and generated code are skipped.

## Example

```csharp
public sealed class Order : Entity<OrderId>
{
    public List<OrderLine> Lines { get; } = [];   // TR302
}
```

```
warning TR302: 'Order.Lines' exposes the mutable collection type 'List<OrderLine>', but rule set 'entities' requires read-only collections
```

## Code fix

**Expose as 'IReadOnlyList&lt;OrderLine&gt;'** changes the declared type to the read-only
equivalent, adding the `using` directive if needed. A target-typed `= new()` initializer becomes
`= new List<OrderLine>()`, since `new()` can't create an interface.

Changing a member's type breaks any code that mutates it through the member, so before offering
the fix it applies the change speculatively and compiles every document that references the
member. **The fix is only offered if that introduces no errors.** When it isn't offered, some
caller still mutates the collection (or an initializer such as `= []` can't target the new
type): that's the code to move into a method on the type.

No fix either for non-generic collections, `virtual`/`abstract`/`override` properties, properties
that implement an interface member, fields declared together with others (`List<int> a, b;`), or
positional record parameters.
