# TR006: Type is declared in the wrong namespace

| | |
|---|---|
| Category | Design |
| Default severity | Warning |
| Code fix | No |

## Cause

A class, struct or record that inherits from or implements a rule set's `match` types is declared
in a namespace that matches none of the rule set's `namespace_pattern` alternatives.

## Why

Conventions like "EF Core configurations live in `*.Database.Configurations`" or "endpoints live
in an `Endpoints` namespace" keep a codebase navigable, and they drift the moment someone adds a
type wherever their editor happened to be. With TR006 the type's base type decides where it
belongs.

## Configuration

```ini
[*.cs]
typerules.configurations.match = T:Microsoft.EntityFrameworkCore.IEntityTypeConfiguration`1
typerules.configurations.namespace_pattern = **.Database.Configurations

typerules.endpoints.match = T:MyApp.Api.IEndpoint
typerules.endpoints.namespace_pattern = **.Endpoints | **.Endpoints.*
```

A pattern is dot-separated names, where:

| Segment | Matches |
|---|---|
| `Orders` | exactly `Orders` (case-sensitive, like C# namespaces) |
| `*` | exactly one segment |
| `**` | any number of segments, including none |

| Pattern | Matches | Doesn't match |
|---|---|---|
| `MyApp.Domain.**` | `MyApp.Domain`, `MyApp.Domain.Orders.Lines` | `MyApp.DomainEvents` |
| `**.Database.Configurations` | `Database.Configurations`, `MyApp.Orders.Database.Configurations` | `MyApp.Database.Configurations.Old` |
| `**.Endpoints.*` | `MyApp.Endpoints.Users` | `MyApp.Endpoints`, `MyApp.Endpoints.Users.Admin` |
| `**` | every namespace, the global one included | — |

Separate alternatives with `|` (or `,`); the namespace has to match at least one. An invalid
pattern is reported as [TR000](TR000.md).

## How it's checked

- The namespace a type is declared in; a nested type uses its outermost type's namespace.
- When a type matches several rule sets with namespace patterns, each one it violates is reported
  separately: unlike accessibility maximums, "must be in `**.Endpoints`" and "must be in
  `**.Handlers`" can't be merged into one requirement.

## Example

```csharp
namespace MyApp.Orders;

internal sealed class OrderConfiguration : IEntityTypeConfiguration<Order> { }   // TR006
```

```
warning TR006: 'OrderConfiguration' is declared in namespace 'MyApp.Orders', but rule set 'configurations' requires a namespace matching '**.Database.Configurations'
```

## Code fix

None. Moving a type to another namespace also means updating the code that uses it, and usually
moving the file. Visual Studio and Rider already do that properly: *Move to namespace* (or
*Move to folder*, when the folder should follow).
