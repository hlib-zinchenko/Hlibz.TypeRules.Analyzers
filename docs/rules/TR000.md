# TR000: TypeRules configuration is invalid

| | |
|---|---|
| Category | Configuration |
| Default severity | Warning |
| Code fix | No |

## Cause

A `typerules.*` key in `.editorconfig` or `.globalconfig` couldn't be applied:

- the key isn't in the form `typerules.<rule set>.<option>`, or the rule-set name contains
  characters other than letters, digits, `_` and `-`
- the option is unknown (e.g. a typo such as `require_seald`)
- a value is invalid: an accessibility option isn't a C# accessibility, a boolean option isn't
  `true`/`false`, or `equality` isn't `value`/`identity`
- the rule set has no `match`, or sets none of `max_accessibility`, `require_sealed`,
  `companion_interface`, `max_setter_accessibility`, `readonly_collections`,
  `namespace_pattern`, `forbid_member_types`, `require_immutable`, `equality` and
  `max_constructor_accessibility` (a rule set another one forbids only needs `match`, and a rule
  set with an unknown option isn't reported for this too)
- the rule set sets only `enabled`, so no rule set by that name is configured (probably a typo)
- the rule set sets `allow_init` without `max_setter_accessibility`
- `forbid_member_types` names a rule set that isn't configured, or `allow_self_references` is set
  without `forbid_member_types`
- a `namespace_pattern` alternative isn't dot-separated names, `*` and `**` (e.g. `App..Orders`,
  `App.Or*`)
- the rule set sets `companion_interface`, but a `match` type is a class rather than an interface
  (a companion interface can only extend interfaces)
- a `match` entry isn't a type ID (`M:...`, `P:...`), names a type that doesn't exist in a
  namespace that does, or names a type nothing can inherit from (a sealed or static class, a
  struct, an enum)

## Behavior

A rule set with any of these problems is ignored entirely, so a typo never leaves it
half-applied. Each distinct problem is reported once per project, naming the first file (by
path, relative to the project) whose settings have it, so you can tell which `.editorconfig` to
look at. For a `match` type that doesn't exist, the closest type name in the same namespace is
suggested.

A `match` type whose namespace doesn't exist in the project is **not** reported. One
`.editorconfig` usually covers several projects, and most of them don't reference every type a
rule set names. That type is skipped in those projects, and the rule set still applies through
its other entries.

TR000 has no source location, because it's about configuration rather than code. It appears in
build output and the Error List, not on a line in the editor.

## Example

```ini
[*.cs]
# Typo in the type name: reported, because namespace MyApp exists.
typerules.endpoints.match = T:MyApp.IEndpont
# Typo in the option name.
typerules.endpoints.require_seald = true
```

```
warning TR000: Invalid TypeRules configuration: unknown option 'require_seald' in rule set 'endpoints' (known options: match, max_accessibility, require_sealed, companion_interface, max_setter_accessibility, allow_init, readonly_collections, namespace_pattern, forbid_member_types, allow_self_references, require_immutable, equality, max_constructor_accessibility, enabled), in the settings for 'Endpoints/GetUserEndpoint.cs'
warning TR000: Invalid TypeRules configuration: rule set 'endpoints' matches type 'T:MyApp.IEndpont', which was not found (did you mean 'T:MyApp.IEndpoint'?), in the settings for 'Endpoints/GetUserEndpoint.cs'
```
